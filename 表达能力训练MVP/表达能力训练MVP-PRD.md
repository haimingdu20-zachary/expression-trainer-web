# 表达能力训练 MVP PRD

版本：MVP 0.1  
定位：面试、工作汇报与高级沟通训练  
原则：保留原有词库与语音识别能力，增加逻辑结构、临场追问、表达重录和报告闭环。

## 1. 产品目标

把原来的“口头表达问题检测器”升级为“实时表达与沟通教练”。用户不仅知道自己哪里说得不好，还能在说话过程中知道下一步应该表达什么，并在结束后通过报告、追问和重录完成一次训练闭环。

## 2. MVP 用户对象

- 想提高工作汇报和会议发言能力的人
- 准备面试、述职、答辩的人
- 想训练观点表达、说服和临场反应的人

## 3. 垂直训练入口

MVP 提供六个入口，每个入口绑定独立的训练目标、表达结构、实时提示和报告重点：

| 入口 | 核心结构 | 重点能力 |
|---|---|---|
| 讲清一个想法 | 观点 → 原因 → 例子/证据 → 总结 | 思路清晰、避免跑题 |
| 面试回答 | 情境/任务 → 行动 → 结果 → 复盘 | 个人贡献、结果和追问应对 |
| 工作汇报 / 述职 | 结论 → 数据/原因 → 风险/案例 → 行动 | 结论先行、数据支撑、行动明确 |
| 会议发言 / 推动决策 | 回应/判断 → 理由/影响 → 方案/依据 → 决策/行动 | 针对问题发言、推动决策 |
| 说服沟通 / 提案 | 问题/主张 → 影响/原因 → 方案/证据 → 行动/收益 | 说服、利益表达、处理异议 |
| 即兴表达 / 随机回答 | 明确回答 → 两个理由 → 具体例子 → 简短收尾 | 临场组织和快速收束 |

## 4. MVP 范围

### 保留能力

- Sherpa-ONNX 离线语音识别
- 实时字幕
- 原有填充词、犹豫词、笼统词分析
- 原有 AI 最终报告
- OpenAI、DeepSeek、Ollama 和自定义 OpenAI 兼容接口
- 自定义训练目标和个人口癖
- 粘贴逐字稿分析

### 新增能力

1. 训练设置：场景、主题、目标时长、表达结构
2. 实时结构导航：结论、原因、例子/证据、总结/行动
3. AI 追问：根据本次表达生成一个最有价值的追问
4. 语速与停顿：估算字/分钟、停顿次数、最长停顿
5. 重录对比：比较前后两次表达的逻辑结构、填充词、字数和语速
6. 报告增强：把训练目标、结构得分、语速、停顿和逻辑问题传给报告模型

## 5. 核心用户流程

```text
选择场景和主题
    ↓
选择表达结构
    ↓
开始录音
    ↓
实时字幕 + 词语反馈 + 下一步结构提示
    ↓
结束录音
    ↓
生成报告 / 请求 AI 追问
    ↓
根据反馈重新录制
    ↓
前后对比
```

## 6. 训练场景与表达结构

### 通用表达 / PREP

结论 → 原因 → 例子/证据 → 总结

### 工作汇报

结论 → 数据/原因 → 风险/案例 → 行动项

### 面试回答 / STAR

情境/任务 → 行动 → 结果 → 复盘

### 说服表达

问题/主张 → 影响/原因 → 方案/证据 → 行动/收益

## 7. 实时结构导航规则

本地规则引擎不依赖模型，基于当前文本、训练结构和时长推断阶段。

| 情况 | 实时提示 |
|---|---|
| 说了较长内容但没有结论 | 先说结论 |
| 有结论但缺少原因 | 补一个原因 |
| 有原因但没有具体支撑 | 来个例子 |
| 内容已经较长但没有收尾 | 开始收尾 |

实时区只显示一个当前最重要的提示，避免用户在表达过程中被多条反馈打断。

## 8. AI 追问规则

AI 追问只在用户主动点击“AI追问”时生成，避免实时过程中的过度打断。

追问优先级：

1. 追问核心结论
2. 追问原因和证据
3. 追问具体案例或数据
4. 追问行动方案
5. 追问风险和反方观点

示例：

> 你说这个方案能提高效率，具体提高了多少？

## 9. 报告需求

最终报告必须继续保留原有报告结构，并新增：

- 本次训练场景、主题和表达结构
- 逻辑结构得分
- 哪个阶段缺失
- 结论、原因、证据、总结的完整性
- 语速、停顿次数和最长停顿
- 最关键的一条训练建议
- 下一次重录时应该重点修正什么

报告仍然是 MVP 的核心功能，不使用实时提示代替最终报告。

## 10. 重录对比

第二次开始录音时，上一轮表达自动作为对比基准。结束后展示：

- 两次完整文本
- 逻辑结构得分变化
- 填充词数量变化
- 语速变化
- 字数变化

后续版本可继续增加句子级差异、结论出现时间和案例数量变化。

## 11. 技术架构

```text
Electron Renderer
  ├── 训练设置
  ├── 字幕和实时 UI
  ├── 语速/停顿采集
  └── 报告、追问、重录对比

Electron Main
  ├── Sherpa-ONNX ASR
  ├── 原有词库分析
  ├── logic-engine.js：实时结构阶段判断
  └── AI API 调用
      ├── 低频实时反馈
      ├── AI 追问
      └── 最终报告
```

### 新增文件和接口

- `lib/logic-engine.js`：四种表达结构与阶段判断
- `analyze-logic` IPC：向渲染层提供结构分析
- `get-followup-question` IPC：生成 AI 追问
- `src/index.html`：训练设置、结构导航、追问和对比 UI
- `src/app.js`：训练状态、交付指标、重录对比

## 12. CLI、CFT、Agent Skill、PE、RAG 是否需要

### CLI

不是产品运行必需。MVP 只需要：

```bash
npm install
npm start
```

后续可以增加 CLI 用于批量分析逐字稿、导出报告和运行回归测试，但现在不影响产品体验。

### CFT / Fine-tuning

MVP 不需要微调模型。当前缺少足够多的用户真实表达数据，直接微调容易把不稳定的评价标准固化。先用规则、Prompt、结构化输出和人工测试集验证产品价值。

### Agent Skill

不需要作为桌面应用运行时依赖。Agent Skill 适合帮助开发者维护 Prompt、测试用例和产品规则，不需要嵌入用户端。

### PE / Prompt Engineering

需要，但不是单独购买的组件。重点是：

- 实时反馈、追问、最终报告使用不同 Prompt
- Prompt 明确训练场景和表达阶段
- 最终报告使用结构化字段
- 限制实时反馈频率和输出长度
- 建立固定的表达测试集评估 Prompt

### RAG

MVP 不需要。实时逻辑判断来自训练结构，不需要检索资料。

后续 RAG 可以用于：

- 用户自己的表达案例库
- 公司汇报模板
- 面试题和岗位要求
- 用户过去的训练记录
- 个人常见问题和历史改进建议

## 13. 模型选择建议

采用“分层模型”而不是一个模型承担所有工作。

| 任务 | MVP 建议 | 原因 |
|---|---|---|
| 语音识别 | 保留 Sherpa-ONNX | 本地、低延迟、已有实现 |
| 实时结构判断 | 本地 `logic-engine.js` | 稳定、即时、零 API 成本 |
| 低频实时反馈 | 低成本、低延迟通用模型 | 只需返回一句提示 |
| AI 追问 | 中等能力通用模型 | 需要理解上下文并提出具体问题 |
| 最终报告 | 更强的通用/推理模型 | 需要逐句分析、综合判断和改写 |
| 本地模式 | Ollama 中等尺寸中文模型 | 隐私和离线，但速度取决于设备 |

OpenAI 当前官方模型文档将模型区分为复杂推理、平衡智能与成本敏感高并发等层级，因此本项目适合把“低成本模型用于实时提示、强模型用于最终报告”作为模型策略，而不是所有请求都使用旗舰模型。[OpenAI 模型文档](https://developers.openai.com/api/docs/models)

DeepSeek 官方文档提供模型列表和结构化输出相关能力，使用 DeepSeek 时应以账户当前可用模型列表为准，不要把模型名永久写死在业务逻辑中。[DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models/)

Ollama 官方文档支持本地模型、流式输出、结构化输出和 Embeddings，适合后续做本地报告和个人历史检索；MVP 阶段先把它作为可选后端保留即可。[Ollama 官方文档](https://docs.ollama.com/index)

## 14. MVP 验收标准

- 用户可以在录音前选择场景、主题和表达结构
- 说话时能看到当前已完成的表达阶段
- 系统能提示“先说结论 / 补原因 / 来个例子 / 开始收尾”等下一步动作
- 结束后可以生成原有完整报告，并包含逻辑结构和交付指标
- 用户点击“AI追问”可以得到一个具体追问
- 用户再次录音后可以打开两次表达对比
- 没有新增词库依赖
- 没有 AI 时，本地字幕和结构提示仍可运行

## 15. 暂不做的内容

- 不扩充情绪词、填充词和笼统词库
- 不做多 Agent 编排
- 不做模型微调
- 不做 RAG 知识库
- 不做社区、排行榜和账号系统
- 不把 AI 实时反馈改成每句话都调用
